## 2. 建议选题：二维 Poisson 方程的 Jacobi 迭代

建议项目名称：**Hybrid MPI–OpenMP Parallelization of a 2D Poisson Solver Using Jacobi Iteration**。

在单位正方形上求解 `-Δu = f`，边界取零。对等间距方形网格，内点更新为：

```text
u_new[i,j] = 0.25 * (u_old[i-1,j] + u_old[i+1,j]
                  + u_old[i,j-1] + u_old[i,j+1] + h*h*f[i,j])
```

采用双缓冲：所有新值都由上一轮值计算；每轮完成后交换 old/new。若支持长方形网格，应使用含 hx、hy 的一般离散公式，不能直接沿用上式。

MPI 把全局网格按行划分给多个进程，每个进程用 OpenMP 更新自己的内点。进程还需保存上下各一行 halo，用来接收相邻进程的边界数据。每轮在本地计算前后安排通信，收敛检测时进行全局归约。

选择该算法的理由：

- 一个网格点依赖邻点，跨进程切分后必须交换数据，符合存在并行挑战的要求。
- 可直接研究计算/通信比例、全局同步、线程调度、内存带宽与进程布局。
- 有已知解，便于独立验证，避免串行和并行程序同时出错却相互“证明正确”。
- 题目范围可控，三人都有代码和分析工作；无需额外引入 GPU 开发环境。

Jacobi 是常见教学算法，不能仅交一个标准示例。项目价值应来自自己实现、规范验证和有针对性的性能实验。如果组员担心题目深度，10/29 前把“算法 + 混合并行 + 设计对比 + 初步实测”发给教师征求意见；不能把本建议当作教师已批准选题。

| 版本 | 内容 | 用途 | 优先级 |

**独立验证建议：** 取 `u*(x,y)=sin(πx)sin(πy)`，连续方程右端为 `f=2π²u*`。零边界满足解析解。收敛解与连续解析解存在离散误差，不能要求机器精度一致；在代数求解误差充分小的条件下，逐次减半 h，检查误差约按二阶减小。

另外可对采样后的 `u*` 应用离散算子构造 `f_h`，得到离散已知解案例，专门检查实现。报告应区分连续解析解验证与离散已知解验证。

至少覆盖：1 rank/1 thread、1 rank/多线程、多 rank/1 thread、多 rank/多线程；内点行数不能整除 rank 数；本地仅 1–2 行；上下物理边界；奇偶迭代次数。若 rank 数大于内点行数，首版可明确拒绝该配置，避免无意产生零行子域。

同样初值与固定步数下，比较完整解的最大绝对误差和相对 L2 误差，不能只比较 checksum。建议先用 `1e-10` 量级的相对/绝对混合容差做小规模 double 精度检查，再依据实际数值尺度冻结标准；不要为了掩盖 bug 随意放宽。

### 6.2 实验矩阵

令 R 为 MPI rank 数、T 为每 rank 的 OpenMP 线程数，CPU 资源记作 P=R×T；在无超额订阅、线程确实绑定至不同物理核的前提下使用该计数。

| 实验 | 固定量 | 变化量 | 要回答的问题 |
|---|---|---|---|
| 串行/MPI/混合对照 | 问题规模、迭代数、编译优化、数值精度 | V0、V1、V2 | 并行总体是否有效？额外开销多大？ |
| 强扩展 | 全局网格、固定迭代次数 K、检查频率 | P，建议至少 4 个可行配置 | 同一工作量增加资源，时间下降多少？何时饱和？ |
| 弱扩展 | 每核内点数近似固定、K 固定、检查频率一致 | P，全局 N 约随 √P 增长 | 工作量和资源同步扩大后，每轮成本是否稳定？ |
| rank/thread 配比 | P、节点数、全局问题、K | R:T，例如 16:1、8:2、4:4、2:8 | 同样资源下哪种组合更合适？ |
| 通信方式 | R、T、节点布局、问题规模、K | Sendrecv 与非阻塞重叠 | 减少等待是否抵消额外开销？ |
| 实际求解 | 同一数学问题、残差阈值和检查频率 | 配置与版本 | 达到同等精度实际需要多久？ |

表中的 16 核配置仅示例，需按实际节点和配额调整。建议先用 256、512 等小网格验证；性能试跑可从 1024、2048、4096 内点每方向开始，根据内存和运行长度选择最终 2–3 个规模，不能把候选规模写成已完成实验。

固定 K 的实验用于隔离并行性能。Jacobi 在更细网格上通常需要更多轮才收敛，因此固定 K 的弱扩展不能直接称为“完整求解器到同精度的弱扩展”；报告分别呈现 kernel scaling 与 time-to-solution。

对一维行划分，即使每核工作量固定，随全局 N 增长，每 rank 的 halo 行也可能变长。因此弱扩展不平坦未必是 bug，可用通信表面积变化解释；二维子域划分是后续可选对照。

### 6.3 指标与公平计时

- 强扩展加速比 `S(P)=t_serial/t_P`；效率 `E(P)=S(P)/P`，串行和并行应执行相同更新任务与收敛检查计划。
- 若大问题串行跑不动，可给相对基线 `S_rel=t_P0/t_P`、`E_rel=S_rel/(P/P0)`，明确标为以 P0 核为基线，不冒充串行加速比。
- 弱扩展效率 `E_weak=t_P0(N0,K)/t_P(NP,K)`，前提是每核工作量近似一致；记录因整数网格产生的偏差。
- 使用墙钟时间；MPI 求解时间取各 rank 时间的最大值。每次测量前统一同步起点，测量结束再归约，不为了计时在每轮额外加入 barrier。
- 核心求解时间包含更新、halo 和既定残差/归约；初始化、验证、文件输出另报。报告清楚写计时边界。
- 采用相同优化级别、精度、初值和数学问题；串行也应合理优化。默认避免使用改变浮点语义的激进选项；若使用必须披露并复验。
- 每个配置建议预热一次、正式重复至少 3 次，条件允许做 5 次，报告中位数与范围/IQR。不要挑最快一次作为唯一结果。
- 阶段耗时可以辅助定位瓶颈，但重叠阶段及不同 rank 的阶段最大值不能直接相加当作总时间，也不宜做误导性的堆叠图。

