 Abstract
 We implement a serial C++17 Jacobi solver and parallel versions using MPI row slabs, OpenMP row
 loops, and two halo exchange methods. The complete mixed validation matrix passes 294 cases and
 five negative cases on Vanda. At N=2048 and 2600 fixed iterations, the fastest tested strong-scaling
 configuration is r2t8, with median solve time 1.073 s and 13.31x speedup over the serial executable.
 Every configuration has one warmup and five measured repetitions. The experiments compare core
 scaling, weak scaling, rank/thread balance, and blocking versus nonblocking communication on one
 CPU node.

 These are measured results from a completed PBS allocation. Fixed-iteration workloads test execution efficiency; a separate
 small-grid convergence experiment tests time to solution. No real dataset is used.

 1. Algorithm and numerical contract
 We solve -Laplacian(u)=f on the unit square with zero Dirichlet boundaries. The grid has N x N interior
 points and spacing h=1/(N+1). A five-point finite difference stencil gives a sparse linear system. Jacobi
 updates each interior value using only the previous iterate, so the update is easy to parallelize locally
 but requires consistent neighbor values across MPI subdomains.

 next[i,j] = (old[i-1,j] + old[i+1,j]
 + old[i,j-1] + old[i,j+1] + h*h*f[i,j]) / 4

 Two solution buffers alternate roles after each sweep. A third array stores the right-hand side. Values
 use double precision and row-major layout, with contiguous columns. The serial cost is O(K N squared)
 for K sweeps, and the principal array storage is approximately 24(N+2) squared bytes. At N=2048, this
 is about 96 MiB before halo and runtime overhead.


 Manufactured solutions
 The continuous test uses u*=sin(pi x) sin(pi y) and f=2 pi squared u*. Its difference from the converged
 discrete solution measures second-order discretization error. Separate discrete sine and asymmetric
 mixed-mode problems use analytically derived discrete eigenvalues; these isolate iteration and
 indexing correctness from discretization error. Zero forcing checks the initially converged case and
 avoids division by zero.


 Stopping and timing
 The relative residual is ||f-Au||2 / ||f||2, with an absolute residual when the forcing norm is zero. Each
 rank forms a local squared sum; MPI_Allreduce sums before taking the square root. Convergence mode
 checks the initial iterate and then the requested intervals. Fixed mode always performs exactly K
 iterations, even when a tolerance happens to be met. A check is forced at the final requested iteration.

 The solve timer includes sweeps, halo exchanges, buffer swaps, scheduled residual evaluations, and
 their reductions. It excludes allocation, right-hand-side initialization and norm, final diagnostics,
 optional gathering, and file output. MPI reports the maximum rank elapsed time, after one starting
 barrier. Serial and standalone OpenMP use the same timer scope. Job duration and MPI process startup
 time are excluded.


 Why parallelization is challenging
 Iterations depend on the previous global state. Halo messages, global convergence reductions,
 synchronization, load balance, and memory locality affect performance. The nonblocking version must
 compute only rows whose inputs are already valid, and must complete sends before old storage can be
 reused. The problem is therefore not embarrassingly parallel.

 2. Parallel design decisions
 MPI decomposition and exchange
 R MPI ranks own contiguous row slabs. Quotient/remainder partitioning gives the first N mod R ranks
 one extra row; ownership differs by at most one row. Each slab keeps an upper and lower ghost row.
 Global row offsets preserve the manufactured forcing, and MPI_PROC_NULL preserves physical
 boundaries. The implementation rejects R>N rather than creating empty owners.

 The Sendrecv method exchanges two rows before updating the entire slab. The overlap method posts
 two receives and two sends, updates interior rows 2 through rows-1, waits for all four requests, and
 updates the boundary rows. One- and two-row slabs have explicit guards, preventing repeated
 updates. Current-solution ghosts are exchanged again before residual evaluation; this straightforward
 implementation retains some repeated communication.


 OpenMP integration
 The MPI driver accepts update, residual, and norm kernels through a LocalKernels interface. The
 OpenMP kernels distribute outer rows with schedule(static), retain contiguous inner-column accesses,
 and use reductions for local sums. Checks run before the parallel region; updates write distinct output
 cells. Dynamic teams are disabled, and the reported team size is probed in a real parallel region and
 checked across ranks.

 The hybrid driver requests MPI_THREAD_FUNNELED and verifies the provided level. All MPI operations
 occur on the initializing thread outside OpenMP regions, consistent with the Open MPI interface [1].
 Loop worksharing has an end barrier [2]. This avoids concurrent MPI calls from worker threads but still
 incurs a parallel-region entry and exit per kernel call.


 Expected tradeoffs
 Each rank performs about N squared/R updates and exchanges up to two N-element rows per sweep.
 Increasing R reduces compute per rank while leaving message length unchanged; global residual
 reductions add latency. At fixed P=R x T, fewer ranks reduce halo boundaries, but more threads add
 barriers and can share memory bandwidth. The nonblocking path can hide transfer time only when
 enough interior work exists and the MPI runtime makes progress. Its separate interior/boundary
 OpenMP calls can cost more than they save.

 We do not use persistent OpenMP teams, explicit SIMD, parallel first-touch, a 2D process grid,
 multigrid, or asynchronous convergence. Array allocation and initialization are serial within each rank.
 These choices keep the baseline auditable and provide concrete explanations for saturation, without
 claiming to have isolated each mechanism experimentally.

 5. Weak scaling and communication method
 Weak scaling keeps approximately 512 squared interior points per core, using N=round(512 sqrt(P))
 and the same K=2600. The maximum rounding error in work per core is 0.021%. Weak efficiency is
 median(t_MPI,1)/median(t_P). It measures fixed-sweep execution, not equivalent PDE convergence as
 the grid is refined.

 For the communication comparison, Sendrecv takes 1.065 s and overlap takes 1.083 s; the blocking/overlap ratio is 0.983. A
 ratio above one favors overlap. Nonblocking communication is not evidence by itself that communication and computation
 progressed simultaneously. The experiment measures complete solve time and does not collect a communication timeline.

 The two observed timing ranges overlap. This run does not demonstrate a robust performance advantage for nonblocking
 exchange. More repetitions with interleaved case order would be needed to assess a small median difference.

 At 16 cores, weak efficiency is 49.8% for MPI and 58.0% for the T=2 hybrid. The overlap median is 1.7% higher than Sendrecv.
 These single-node results combine memory, cache, synchronization, and communication costs. More MPI ranks shrink the
 independent interior; more threads increase region coordination. No bandwidth counters or NUMA experiment were collected, so
 these are possible mechanisms rather than established hardware causes.

 Conclusions and limits
 The implementation is numerically validated across serial, MPI, standalone OpenMP, and hybrid
 execution. On the tested Vanda allocation, r2t8 gives the lowest strong-study median, while r1t16
 leads the fixed-16-core comparison. The data demonstrate that the rank/thread balance and
 communication path are experimental choices, not automatic improvements. All conclusions apply to
 these grid sizes, source revision, compiler, placement, and one CPU node.

 We have not measured multi-node scaling or GPU execution. Open MPI logs warnings about unavailable
 PBS/UCX plugins; single-node execution and actual rank affinity were verified, but inter-node
 placement and network overlap have not been validated. The node is not reserved in its entirety. Case
 order is sequential, samples are limited to five, and no hardware counters or frequency controls are
 used. Follow-up work should test multiple nodes, randomized study order, parallel first-touch,
 persistent thread teams, and a 2D decomposition.

 All inputs are manufactured numerical problems. There is no real dataset from which to draw
 application-domain conclusions. The results concern solver correctness and parallel execution
 efficiency.
