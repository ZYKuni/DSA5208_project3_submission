## P0 实施细节

1. 混合组合增加在现有 scenarios 中，仍按 ranks 过滤 N，并保留窄子域、K=0/奇偶、mixed/zero、收敛/未收敛。逐套检查真实输出，不能仅数返回码。总案例数由实际 summary 生成，不提前写死。
2. 四种构建分别使用新的独立 build 目录，明确 MPI/OpenMP ON/OFF，避免 CMake 缓存污染。OpenMP-only 不要求 MPI；串行和 MPI-only 不得意外运行线程测试。
3. 小核数 CI 可允许超额订阅，并对正确性测试设置 OMP_WAIT_POLICY=PASSIVE，减少此前 Vanda 小分配中遇到的等待竞争；记录设置、检查超时，不为通过测试放宽数值容差。不能把这些运行作为性能数据。
4. 现有 EXIT trap 仅归档 mpi-validation/Testing；新增 parallel-acceptance 的完整/紧凑证据保存，包括运行未结束或 summary 缺失时已有 stdout/stderr/verdict。
5. 核对输出身份：当前 hybrid --kernel serial 的 variant 与 MPI-only 可相同，kernel/driver 也可能无法唯一指明入口。先确保验收/采集 manifest 保留 executable 路径及哈希，审核报告没有把不同入口混作一个版本；如新增入口字段，须同步读者并验证兼容，不擅自改历史日志。
